Rust core · Go connectors

wuphf

A multi-platform messaging replication engine. It models one logical message and its copies across platforms — so edits, deletes, replies, and identity migrations stay coherent instead of degrading into blind forwarding.

Architecture → Connector protocol README

01The big idea

Most bridges forward a message from A to B and forget it. wuphf instead keeps a single internal identity for every message and tracks each platform-specific copy of it. That record is what makes an edit on WhatsApp become an edit on Telegram — not a duplicate.

02Core concepts

Four ideas carry the whole model. Everything a connector sends is resolved down to these by the core.

◆Logical message

A core-owned MessageId. Each delivered or received platform form is a MessageCopy keyed by (MessageId, EndpointId, platform_message_id).

◆Endpoint & Alias

An internal handle for one chat (optionally a thread) on one connector. Connectors only ever send raw addresses; an Alias resolves them — many aliases can point at one endpoint, so a phone-to-LID migration changes nothing downstream.

◆Replica set

The set of endpoints that mirror each other. A message delivered to one member fans out to all the others — and never back to the origin.

◆Conversation

The abstract unit a rule pairs across sides — one per source chat — backed by exactly one replica set.

03Routing rules

Rules are the only routing input you write. Conversations, endpoints, and replica sets are derived lazily at runtime. Each rule pairs two or more sides; each side names a connector and a kind.

single

One fixed chat, optionally one thread within it.

source

Every real chat on a connector, filtered by explicit include/exclude id lists. Owns conversation identity.

mirror

One threaded container; the core provisions one thread per source conversation. Needs a connector that supports topic creation.

The canonical topology is source → mirror: every WhatsApp chat mirrored into its own Telegram forum topic.

# every allowed WhatsApp chat → its own Telegram forum topic [[rules]] id = "wa-to-telegram-mirror" [[rules.sides]] connector = "whatsapp-main" kind = "source" [[rules.sides]] connector = "telegram-main" kind = "mirror" container = "telegram:channel:2060340733"

06Replicated operations

Create, edit, and delete are replicated across the set. How each target renders an edit or delete is set per connector and resolved directionally at routing time — never forced symmetrically onto a replica set.

✎Edit modes

in_place revises the existing copy; repost leaves it and posts the revision as a reply marked as an edit.

⌫Delete modes

revoke removes the copy; tombstone leaves it and posts a deletion notice.
